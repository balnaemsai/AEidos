# AEidos 게임 계획서 v2

기존 게임 계획서의 구조와 핵심 내용을 유지하되, 구현 과정에서 확정되거나 추가된 사항만 보강한 통합 문서다. 원안의 기획 의도를 기준으로 삼고, 현재 프로젝트에 실제 반영된 시스템은 각 섹션의 `현재 구현 반영` 항목에 정리한다.

## 1. 게임 개요

- 게임 제목: `Eidos` (가제)
- 장르: 정착지 경영 + 던전 탐험 + 약탈
- 플랫폼: PC (향후 콘솔/모바일 이식 가능)
- 이용 엔진: Unreal Engine 5
- 플레이 방식: 싱글 플레이 (추후 비동기 PvP 확장 가능)
- 한 줄 설명: `림월드 + 다키스트 던전`
- 목표 유저층: 하드코어 생존/경영 장르 유저를 중심으로 하되, 커스텀 난이도나 모딩을 통해 캐주얼한 건설/경영 플레이도 가능하도록 개발

### 핵심 컨셉

차원의 도서관에서 새로운 세계인 `책` 하나를 부여받아 그 안에 정착지를 건설하고 성장시키는 동시에, 다른 차원의 정착지를 던전 형태로 탐험하고 약탈하며 발전을 이어가는 전략형 경영 게임.

### 현재 구현 반영

- 정착지 운영, 포탈 생성, 던전 진입, 적대 정착지 프리셋 복원, 기초 턴제 전투까지의 뼈대가 실제 프로젝트에 반영되어 있다.
- 플레이어가 직접 조작하는 `Page` 중심 구조와 정착지-던전 이중 루프가 실제 코드 구조의 중심이 되었다.

## 2. 게임 배경 및 세계관

### 2.1 세계관 개요

모든 세계는 `차원의 도서관`에 보관된 무수한 책 속에 존재한다. 각 책은 하나의 완전한 차원을 담고 있으며, 그 안에는 고유한 생태계, 주민, 문화가 존재한다. 플레이어는 차원의 도서관장과 만나 `도서관 관리인 후보`로 임명되고, 하나의 빈 책을 부여받는다. 이 책 속 세계가 바로 플레이어의 정착지이며, 플레이어는 이를 번영시키는 책임을 가진다.

### 2.2 던전의 정체

`던전`은 사실 다른 책 속 세계, 즉 다른 차원의 정착지를 기반으로 재현된 시뮬레이션 공간이다. 설정상 플레이어는 도서관의 권한으로 다른 차원으로 이어지는 포탈을 생성해 약탈 가능하다. 따라서 던전 구조, 주민, 방어시설은 해당 세계를 모사하지만 실제 피해는 원본 세계에 가지 않는다. 약탈 성공 시 그 차원에서 사용되는 자원, 기술, 설계도 등을 가져와 자신의 세계에 적용할 수 있다.

### 2.3 스토리 흐름

- 튜토리얼: 도서관장과의 대화를 통해 세계 구조, 자원 순환, 던전 공략법을 배운다.
- 차원 할당: 하나의 빈 책을 부여받고 해당 세계에 첫 발을 디딘다.
- 성장과 침공: 다른 차원의 복제 던전을 공략하여 자원을 확보하고, 이를 바탕으로 자신의 세계를 발전시킨다.
- 위협 등장: 일정 발전 이후 던전을 기한 내에 공략하지 못하면 경고가 주어지고, 실패 시 다른 차원의 존재가 플레이어의 세계를 역으로 침공한다.
- 비밀 발견: 던전을 탐험하며 차원의 도서관의 숨겨진 의도와 다차원 간 전쟁의 진실을 알아간다.

### 현재 구현 반영

- 포탈은 정착지에서 실제로 주기적으로 생성되며, 플레이어는 직접 상호작용해 던전에 진입할 수 있다.
- 던전은 일반적인 미궁이 아니라 적대 정착지 프리셋을 복원하는 방향으로 구현이 진행 중이다.

## 3. 핵심 게임 메커니즘

### 3.1 자원 수집 & 던전 탐험

#### 3.1.1 자원 시스템

자원은 기본적으로 `기본 자원`과 `아이템형 자원` 두 가지로 나뉜다.

- 기본 자원: 식량, 목재, 석재, 금속, Eidos(차원 에너지) 등
- 아이템형 자원: 설계도, 특수 광물, 특수 부품 및 재료 등

자원 특징:
- 분당 생산량과 보관 한도 존재
- 건설, 업그레이드, 유닛 유지비, 연구에 사용
- 캐릭터는 생산 건물 작업이나 던전 수집을 통해 자원을 획득
- 자원은 부피를 지니며, 창고 수와 레벨에 따라 수납 가능량 증가

##### 현재 구현 반영

- 현재 프로젝트는 `Food`, `Wood`, `Stone`, `Metal`, `EP`를 중심 자원으로 사용 중이다.
- `EP`는 영토 확장과 특수 비용의 기반 자원으로 사용된다.
- 자원 데이터는 CSV 기반 편집 후 Unreal DataTable로 reimport 가능한 형식이 마련되어 있다.

#### 3.1.2 건설

##### 3.1.2.1 영토

영토는 유저가 건물을 설치하고 이동하는 등 다양한 활동이 가능한 범위를 의미한다.

- 기본 시작 크기: `10m x 10m`, 즉 1청크
- 존재 포인트(`Eidos`)를 이용해 정착지 확장 가능
- 확장 시 아무것도 없는 반투명 바닥 공간이 생성됨
- 바닥은 파괴 불가능하나, 지하 확장 시 제거 가능
- 기본적으로 확장 한도는 없지만, 과도한 영토는 정착지 가치 상승과 세금형 Eidos 차감으로 불이익 가능
- 시나리오에 따라 최대 확장 크기 제한 가능
- 처음 지급되는 영토 청크는 `Y=0`에 깔리는 반투명 바닥이며, 위로는 제한 없이 확장 가능
- 지하 확장은 추가 존재 포인트와 별도 구조를 통해 진행

##### 현재 구현 반영

- 영토는 `OwnedChunks` 기반으로 관리된다.
- 확장 가능한 청크는 현재 보유 청크와 인접한 청크로 제한된다.
- 영토 확장은 Build 흐름과 유사하게 프리뷰 후 좌클릭으로 확정된다.
- 다른 건물과 달리 작업 큐를 거치지 않고 즉시 완성되지만, `EP 100` 비용을 차감한다.

##### 3.1.2.2 건물

플레이어는 일정 자원을 소모해 영토 내에 특정 건물들을 건설할 수 있다.

- 건물은 크기가 서로 다르다.
- 이미 건물이 설치된 위치에는 설치할 수 없다.
- 건물마다 소모 자원과 건축 시간 다름.
- 건물 분류:
  - 생산 건물
  - 군사 건물
  - 연구 건물
  - 방어 건물
  - 특수 건물
  - 건축 건물

##### 현재 구현 반영

- Build 패널에서 건물 목록을 읽고 월드 프리뷰를 통해 배치할 수 있다.
- 건물은 DataTable 기반으로 비용, 설명, 작업량, 액터 클래스를 관리한다.
- 실제 건설은 작업 시스템과 연계되어 ConstructionSite -> 작업 수행 -> 건물 완성 흐름을 따른다.

#### 3.1.3 던전

던전은 던전 포탈을 통해 이동할 수 있으며, 플레이어의 정착지를 제외한 `정착지 형태의 공간`이다.

##### 3.1.3.1 던전 생성

- 던전은 다른 플레이어의 정착지 구조를 모사하여 생성됨
- 생성 방식:
  - 개발자 프리셋 풀에서 난이도에 맞춰 랜덤 선택
  - 다른 플레이어 정착지 데이터 기반(비동기 PvP)
- 초반에는 다른 플레이어 데이터가 없으므로 프리셋 풀에서만 제공
- 기본적으로 미리 제작된 프리셋 타일맵 또는 정착지 구조를 기반으로 생성
- 플레이어가 직접 던전을 선택하지 않음
- 정착지 가장자리의 무작위 위치에 차원 포탈이 주기적으로 생성
- 포탈이 폭주하기 전 던전을 클리어하지 못하면 역침공 이벤트 발생
- 던전은 플레이어 기지가치에 비례한 위험도를 가진다
- 건물, 방어 설비, 유닛, 환경 요소가 던전 난이도에 반영됨
- 던전 테마는 몇 종류로 분류되며, 연구를 통해 특정 테마 등장 확률 조절 가능
- 종류와 수치는 CSV로 관리 예정

##### 현재 구현 반영

- 포탈은 고정틱 시뮬레이션에 연결되어 자동 생성된다.
- 포탈 생성 위치는 플레이어 위치가 아니라 `정착지 중심` 기준으로 잡히도록 수정되었다.
- 던전은 `DungeonRuntimeBase` 위에 프리셋 데이터를 런타임 복원하는 구조다.
- 프리셋은 `DungeonSettlementPreset` 자산으로 저장되며, 청크/건물/Entry/Core/EnemySpawn를 포함한다.
- 저작용 맵에서 `AuthoringActor + Marker`로 프리셋을 저장할 수 있다.

##### 3.1.3.2 던전 공략

- 플레이어는 일정 수의 캐릭터를 원정대로 편성해 던전 공략에 투입할 수 있다.
- 플레이어는 직접 컨트롤 공략 또는 자동 공략을 선택할 수 있다.
- 자동 공략 시 시간과 성공률은 원정대 전투력에 따라 달라진다.
- 던전 공략의 핵심 목표는 `던전 코어` 파괴 및 획득이다.
- 코어 파괴 후 복귀용 차원 포탈이 생성되며, 일정 시간 뒤 던전은 소멸한다.
- 던전 코어는 테마에 따라 속성을 지니고, 특정 건물 건설 조건으로 사용 가능하다.
- 던전 코어 위치는 공개되지 않으며, 탐색 후 수색해야 한다.
- 던전 포탈에서 던전 코어까지는 사람 크기의 페이지가 지나갈 수 있는 최소 한 개의 경로가 존재해야 한다.
- 던전 내 블록은 페이지에 의해 파괴 및 수확 가능하며, 일부는 도구가 필요하다.
- 수집한 자원은 인벤토리 허용량만큼 휴대하여 반출할 수 있다.

##### 현재 구현 반영

- 현재는 포탈 입장 시 선택된 Page 1명을 던전으로 이동시키는 흐름이 구현되어 있다.
- 적 스폰 마커 기반으로 던전 내 적 유닛 생성이 가능하다.
- 코어 파괴, 귀환, 자동 공략, 루팅은 아직 본격 구현 전 단계다.

### 3.2 정착지 성장

- 자원을 통해 건물 건설과 업그레이드 가능
- 기본 시작 크기는 1청크이며 Eidos를 통해 영토를 확장 가능
- 확장 시 반투명 바닥 공간이 생기고, 지하 확장도 가능
- 지나친 영토 확장은 불이익 가능
- 시나리오에 따라 최대 크기 제한 가능

#### 3.2.1 인구 시스템

- 인구는 생산력과 군사력의 기반이다.
- 인구 한도는 주거지 업그레이드 등으로 증가한다.
- 인구는 작업 종류나 건물 작업 할당을 통해 배치된다.
- 정착지의 인구만큼 페이지를 보유할 수 있다.

##### 현재 구현 반영

- 현재는 테스트용으로 새 게임 시작 시 Page 2명을 지급한다.
- Population 시스템은 Page 수집, ID 관리, 작업 배정, 기본 상태 갱신을 담당한다.

#### 3.2.2 페이지

Page는 유저가 컨트롤 가능한 아군 최소 유닛 단위다.

- 각 페이지는 내구, 이동 속도 등의 스탯을 가진다.
- 스탯은 재능치와 스킬 숙련도의 영향을 받는다.
- 페이지 자체의 레벨은 없지만, 행동을 통해 관련 스킬 숙련도를 올릴 수 있다.
- 페이지는 특성을 가질 수 있다.
- 페이지는 전투력과 생산 관련 가치를 함께 가진다.
- 기본적으로 랜덤한 한 명의 페이지로 시작하지만, 시나리오나 튜토리얼에 따라 초기 인원은 달라질 수 있다.
- 플레이어는 각 페이지를 선택하여 1인칭/3인칭 쿼터뷰로 시점을 전환하며 조작할 수 있다.
- 선택한 1명의 페이지를 제외한 나머지는 AI가 행동한다.
- 페이지는 사망 시 영구 사망을 기본으로 하되, 머리 또는 몸통 내구가 처음 0이 되었을 때는 일정 시간 `가사` 상태에 접어들 수 있다.
- 각 페이지는 무게 한도의 인벤토리를 가진다.
- 각 페이지는 작업 우선순위와 작업대 고정 등의 지시를 받을 수 있다.
- 페이지 습득 방법: 던전 포획-교섭, 번식, 방랑 상인과의 거래 등
- 고통 한계 초과 시 기절 및 포획 가능 상태

##### 현재 구현 반영

- 페이지 선택 전환은 `[`와 `]` 키로 가능하며, 선택 즉시 카메라가 해당 페이지를 따라간다.
- 페이지는 던전 안/밖 상태를 구분하며, 던전 안에 있는 페이지는 정착지 작업에서 제외된다.
- 선택된 페이지가 죽을 경우 다른 사용 가능한 페이지로 카메라와 선택이 자동 전환되도록 보완되었다.
- 현재 구현된 페이지 기능은 이동, 선택, 작업 상태, 던전 상태, 전투 행동 슬롯 중심이다.
- 인벤토리, 장비, 포획/포섭, 특성, 상세 생존 시스템은 아직 본격 구현 전이다.

#### 3.2.3 스킬

- 스킬은 패시브 스킬과 액티브 스킬로 나뉜다.
- 패시브 스킬은 상시 발동하며, 관련 행동을 할 때 숙련도가 빠르게 상승한다.
- 액티브 스킬은 유저가 발동하거나 AI가 특정 상황에서 발동한다.
- 스킬에는 상위-하위 위계가 존재한다.
- 하위 스킬 숙련도가 오를 때 상위 스킬 숙련도도 상승한다.
- 기본 스킬 몇 가지를 제외한 스킬은 특정 조건이 갖춰져야 해금된다.

##### 현재 구현 반영

- `DT_Skill` 기반 데이터 구조가 존재하며, CSV import/reimport 가능 형식이 마련되어 있다.
- 액티브 전투 스킬을 위해 AP 비용, 사거리, 타깃 필요 여부, 데미지 등 전투용 필드가 추가되었다.
- 페이지는 10개의 전투 행동 슬롯을 가지며, `1~0` 입력으로 슬롯 실행이 가능하다.

#### 3.2.4 특성

- 특성은 캐릭터가 고유하게 가지는 태그나 칭호에 가까운 개념이다.
- 스탯에 직접 영향을 주기보다 행동의 방향과 효과에 영향을 준다.
- 태어날 때부터 보유하거나, 후천적 조건 달성 시 습득할 수 있다.

##### 현재 구현 반영

- 특성 시스템은 아직 본격 구현되지 않았으며, 향후 Page 고유성, 포획/포섭, 전투 스타일 차별화의 핵심 요소가 될 예정이다.

#### 3.2.5 작업

작업(Work)은 일정 입력값을 받아 정착지에 활용할 자원 또는 진행도로 변환하는 스키마다.

- 페이지에게 작업을 할당하면 `일(Job)`이 된다.
- 각 페이지는 우선순위가 높은 일부터 수행한다.
- 작업은 연구, 건물, 페이지 특성 등에 따라 해금된다.
- 작업은 자원이나 진행도, 스탯 상승 등을 출력값으로 가진다.
- 작업 큐는 횟수/충족/반복 방식으로 예약 가능하다.

##### 현재 구현 반영

- Work 시스템은 정착지 시뮬레이션의 핵심 축으로 구현되어 있다.
- 건설은 Work를 통해 진행되며, 페이지 작업 상태와 연계된다.
- 영토 확장은 Build UX를 따르지만 작업 큐를 거치지 않는 별도 경로다.

### 3.3 위협 시스템 (역침공)

- 일정 기한 내에 던전을 공략하지 않으면 해당 차원의 존재가 플레이어 세계를 습격한다.
- 레이드 강도는 던전 위험도에 따른다.
- 플레이어는 던전을 공략해 레이드를 막거나, 정착지 포탈 주변 방비를 강화해 대비할 수 있다.
- 레이드는 여러 웨이브로 구성된다.
- 포탈 주변 5m에는 건물 건설이 불가능하며, 포탈에서 던전 코어까지 적어도 하나의 경로가 존재해야 한다.

##### 현재 구현 반영

- 포탈에는 `RaidTriggered` 상태까지 포함된 상태 머신이 적용되어 있다.
- 다만 실제 역침공 본체, 웨이브, 정착지 방어전은 아직 미구현 단계다.

### 3.4 전투

- 전투는 기본적으로 턴제이며, 정착지 운영 중에는 실시간, 전투 상황에서는 턴제로 전환된다.
- 전투 중인 파티는 턴에 따라 일시정지된 상태지만, 전투 밖의 페이지는 실시간으로 이동 가능하다.
- 첫 공격이 발생하면 전투가 시작되고, 기민 스탯과 행동 능력에 따라 턴 순서가 계산된다.
- 각 유닛은 행동 역치만큼의 행동력을 사용해 이동, 스킬 사용, 물품 사용 등을 수행할 수 있다.
- 전투 외부 유닛이 일정 반경 내로 들어오거나, 전투 중 유닛에게 영향을 주는 행동을 하면 난입할 수 있다.
- 턴 제한 시간은 기본 60초이나 시나리오에 따라 조정 가능하다.
- 적대 유닛이 모두 사망하거나 이탈하면 실시간 모드로 복귀한다.
- 일부 아군 유닛은 AI에 맡길 수 있다.
- 실시간 모드와 턴제 모드에서 가능한 행동 목록은 동일하다.

##### 현재 구현 반영

- 현재 전투는 AP 기반 턴제의 기초 버전이 구현되어 있다.
- 적은 자동으로 행동하고, 아군은 플레이어가 슬롯 입력으로 행동을 선택한다.
- 아군의 자동공격은 제거되었고, 기본 공격 대신 행동 슬롯 실행 구조로 전환되었다.
- 전투 참가자와 비참가자 구분은 아직 정교하게 다듬어야 한다.
- 원안에 있는 기민 기반 세밀한 턴 카운팅은 아직 전체 구현되지 않았고, 현재는 simpler turn/AP 구조가 먼저 들어간 상태다.

### 3.5 시나리오

- 게임 시작 시 플레이할 시나리오를 선택할 수 있다.
- 시나리오마다 승리/패배 조건이 다르다.
- 예시:
  - `집필`: 차원 연구 후 도서관 던전 코어 파괴
  - `생존`: 무한 에이도스 생성기 건설
  - `이야기는 계속된다`: 던전 코어 체력이 무한
  - `주인공`: 특정 페이지 사망 시 패배

##### 현재 구현 반영

- 현재는 시나리오 분기보다는 공통 코어 시스템 구현이 우선되어 있다.
- 향후 저장 구조, UI, 승패 조건 시스템과 함께 연결되어야 한다.

## 4. 플레이 방식

- 시점: 기본 캐릭터 고정 3인칭 쿼터뷰 / 1인칭 전환 가능 / 특정 키로 자유 시점 해제 가능
- 선택한 캐릭터 상태에서 퀵바를 이용한 아이템 또는 스킬 사용 가능
- 던전 공략과 정착지 경영은 동시에 가능
- 캐릭터 선택 전환이나 자유 시점을 통해 정착지와 던전 사이를 수시로 전환 가능
- 기본적으로 미니맵은 제공하지 않음
- 플레이어가 바라보는 방향의 벽은 하단만 보이는 투명벽 처리
- AI는 가장 가까운 적을 우선 공격하되, 정책 지시에 따라 패턴 변화
- 난이도 3계층: Easy / Normal / Hard
- 기본 세션은 던전 탐험 → 보상 활용 → 경영의 흐름으로 약 20분 정도를 목표로 함
- 하루는 60분이며, 밤 8시 ~ 아침 6시는 밤 판정
- 기본 세이브/로드 가능, 철인 모드 등 특수 시나리오 존재
- 배속은 1배/2배/4배 사용 가능, 전투 중에는 1배 고정
- `GameTick` 개념 존재, 현실 1초 = 게임 시간 24초

### 진행 구조

- 튜토리얼: 도서관장 설명 → 첫 책 할당 → 초보 던전 공략 → 페이지 1명 포획 및 교섭
- 탐험 단계: 던전 선택 → 전투 & 약탈 → 귀환
- 경영 단계: 자원 분배 → 건물/병력/기술 업그레이드 → 반복
- 위기 단계: 기한 내 던전 미공략 시 역침공 발생
- 스토리 확장: 특정 조건 달성 시 차원의 비밀 개방

### 성장 곡선

- 초반: 약한 차원의 던전, 기초 자원 확보
- 중반: 중간 난이도 던전, 희귀 기술/설계도 획득, 방어 설비 강화, 기술 연구
- 후반: 고난이도 던전, 대규모 역습, 엔딩 스토리

### 유저 플레이 흐름

- 1차 목표: 자동적으로 지속 가능한 정착지 구현
- 2차 목표: 전투력 상승, 고등급 자원 및 기술 해금
- 3차 목표: 해당 등급 던전을 저위험 자동 공략 가능 상태 달성
- 최종 목표: 엔딩을 위한 파이널 던전 공략

전투력 상승 요소:
- 페이지 수 증가
- 좋은 특성/재능을 가진 페이지 영입
- 페이지 스킬 레벨 육성
- 높은 품질의 무기 제작
- 고밸류 사용 아이템 제작 및 획득
- 방어용 함정 및 건물 업그레이드

### 튜토리얼 (기본 시나리오 기준)

- 월드 생성
- 유저 커스터마이징 페이지 1명과 사전 생성된 던전 포탈 1개 존재
- 기본 조작법 및 UI 설명
- 던전 포탈 설명 및 진입
- 내부에 돌/나무/음식/물/적대 페이지 1명 배치
- 전투 튜토리얼
- 승리 시 기본 파밍법과 던전 코어 파괴 유도
- 적대 페이지는 거의 무조건 포획 가능하도록 유도
- 던전 코어 파괴 후 제한 시간 설명 및 탈출 유도
- 빨리감기와 포로 교섭 기능 설명
- 포로 교섭 시 튜토리얼 종료

### 현재 구현 반영

- 1인칭/3인칭 전환 및 자유 시점 계열 입력은 구현되어 있다.
- 1인칭 조작과 UI 상호작용이 모두 가능하도록 입력 모드가 상황별로 조정되었다.
- 현재는 여러 Page를 직접 전환하며 정착지와 던전을 오갈 수 있다.
- 퀵바는 향후 팝업 중심 UI로 정리할 예정이며, Pages 패널에서 슬롯 편집을 담당하는 방향이 잡혀 있다.

## 5. 아트 & 사운드 방향

- 던전은 적대 정착지 구조를 가지되, 하늘과 대기를 더 이질적으로 연출해 정착지와 감각적으로 구분하는 방향으로 잡혀 있다.

## 9. 최종 요약

AEidos는 `정착지 운영`, `포탈 대응`, `적대 정착지형 던전 공략`, `Page 성장`, `전투와 약탈`을 하나의 루프로 묶는 게임이다. 기존 계획서의 핵심은 그대로 유지되며, 현재는 그중 정착지 운영, 포탈, 던전 진입, 적대 정착지 프리셋, 다중 Page 운용, 기초 턴제 전투까지 실제 구현이 진행된 상태다. 앞으로는 UI, 던전 목표 루프, 포획/포섭, 역침공, 메타 진행 요소를 완성해 전체 경험을 닫는 것이 핵심 과제다.
